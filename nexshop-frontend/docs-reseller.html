Apa itu Program Reseller NexShop?

Program Reseller NexShop adalah solusi kemitraan digital bagi konter pulsa, toko online, admin grup jualan, dan developer aplikasi yang ingin menjual ulang seluruh produk PPOB dan voucher game NexShop dengan harga modal khusus reseller.

auto_graph Konsep Kemitraan

Setelah akun Anda disetujui, harga di seluruh etalase (Marketplace & Topup Diamond Game) otomatis dipotong sesuai tingkatan tier diskon saat Anda login. Anda bebas menentukan harga jual sendiri ke pelanggan untuk mendapatkan margin keuntungan maksimal.

Cara Mendaftar Menjadi Reseller

Pendaftaran program reseller NexShop 100% gratis tanpa dipungut biaya apapun.

1

Miliki Akun NexShop & Login

Pastikan Anda sudah mendaftar dan memiliki akun pengguna di NexShop melalui halaman Masuk / Daftar Akun.

2

Buka Formulir Pendaftaran Reseller

Masuk ke halaman Pendaftaran Reseller, lalu lengkapi: Nama Lengkap, Nomor WhatsApp aktif, Nama Usaha/Konter (opsional), Kanal Penjualan, dan Estimasi Transaksi Bulanan.

3

Peninjauan oleh Admin (Maks. 1×24 Jam)

Tim admin NexShop akan meninjau pengajuan dan menghubungi nomor WhatsApp yang Anda daftarkan untuk verifikasi data.

✓

Status Aktif & Siap Berjualan

Begitu disetujui, akun Anda langsung bertransisi menjadi akun Reseller. Anda dapat langsung melihat harga khusus reseller di seluruh katalog saat masuk ke akun.

sell Bab 4

Tingkatan Tier & Diskon Reseller

Diskon reseller dihitung otomatis oleh server NexShop di setiap produk berdasarkan tier tingkatan akun Anda.

calculate Rumus Perhitungan Diskon

Harga Reseller = Harga Normal × (1 − Diskon%)

Contoh: Jika harga normal produk adalah Rp100.000 dan tier akun Anda memiliki diskon 5%, maka harga yang Anda bayar di NexShop adalah Rp95.000.

Tingkatan Tier Persentase Diskon Deskripsi & Fasilitas
progress_activity Memuat data tier reseller aktif...
shield
Proteksi Margin Aman: Pada produk dengan margin sangat tipis (seperti pulsa transfer atau PLN tertentu), sistem server menerapkan batas pengaman otomatis agar harga reseller tetap berada dalam ambang batas modal supplier.

Cara Menggunakan Akun Reseller

Penggunaan akun reseller sangat mudah dan terintegrasi penuh di halaman web:

1

Masuk ke Akun (Login)

Selalu pastikan Anda dalam kondisi Login sebelum melihat katalog atau checkout. Jika belum login, sistem akan menyajikan harga pembeli umum.

2

Periksa Penanda Harga Reseller

Banner konfirmasi "Harga Reseller Aktif" akan muncul di bagian atas halaman Marketplace dan Topup Game. Harga normal yang dicoret akan tampil berdampingan dengan harga reseller Anda.

3

Checkout & Bayar Pesanan Pelanggan

Masukkan data tujuan milik pelanggan Anda (Player ID game, No. HP, No. Rekening, atau No. Pelanggan), lalu bayar menggunakan metode pembayaran pilihan (QRIS / VA). Produk akan langsung terkirim ke akun pelanggan.

Penjelasan API Endpoints NexShop

Bagi reseller atau toko mitra yang ingin menghubungkan aplikasi/website sendiri secara langsung ke server NexShop, berikut adalah daftar endpoint utama yang tersedia:

GET /api/reseller/tiers

Mengambil daftar semua tingkatan tier reseller aktif, persentase potongan diskon, dan deskripsi fasilitas masing-masing tier.

Contoh Response (JSON) 200 OK 
[
  {
    "code": "silver",
    "name": "Reseller Silver",
    "discount_percent": 3.0,
    "description": "Tier awal reseller baru"
  },
  {
    "code": "gold",
    "name": "Reseller Gold",
    "discount_percent": 5.0,
    "description": "Tier untuk reseller dengan transaksi aktif"
  }
]
GET /api/topup/catalog

Mengambil seluruh daftar kategori dan produk (Topup Game, Pulsa, E-Wallet, PLN, Transfer Bank). Jika Anda menyertakan header Authorization: Bearer <token> milik akun reseller, harga yang dikembalikan di field reseller_price otomatis terhitung sesuai tier akun Anda.

POST /api/topup/inquiry

Melakukan pengecekan tagihan sebelum bayar (khusus tagihan PLN Pascabayar, PDAM, BPJS Kesehatan, dan Telkom).

Request Body (JSON) application/json 
{
  "kode_produk": "PLNPASCA",
  "nomor_pelanggan": "51234567890"
}
POST /api/topup

Membuat order/transaksi baru untuk semua produk digital. Sistem akan mengembalikan ID pesanan, total bayar, status, serta detail QRIS / VA.

Request Body (JSON) application/json 
{
  "kode_produk": "ML86",
  "tujuan": "12345678",
  "server_id": "2123",
  "payment_method": "qris"
}
GET /api/topup/order/:id

Mengecek status terkini suatu pesanan berdasarkan ID Pesanan (status: pending, paid, success, atau failed) beserta nomor SN resminya.

Konsep & Alur Webhook Relay

Bagi reseller yang mengoperasikan website toko online, aplikasi Android/iOS, atau bot WhatsApp/Telegram sendiri, NexShop menyediakan layanan Webhook Relay terpusat.

hub Mengapa Menggunakan Webhook?

Layanan Webhook Relay NexShop memungkinkan sistem Anda menerima pembaruan status transaksi secara otomatis dan instan tanpa perlu melakukan polling berulang-ulang. Setiap kali pesanan diproses oleh sistem backend NexShop, server kami langsung mengirimkan notifikasi HTTP POST ke URL callback yang Anda daftarkan.

route Routing Berdasarkan Prefix ref_id

Agar server Anda hanya menerima callback transaksi milik toko Anda sendiri, setiap transaksi dapat diberi prefix unik pada ref_id (misalnya: MYSTORE-10293). Relay NexShop akan mencocokkan prefix tersebut dan hanya mem-forward callback ke endpoint URL Anda.

Verifikasi Signature Kriptografis (HMAC SHA-256)

Untuk memastikan webhook benar-benar berasal dari server NexShop dan tidak diubah di tengah jalan (man-in-the-middle), setiap request menyertakan header X-NexShop-Signature.

vpn_key Rumus Pembuatan Signature

NexShop membuat signature dengan menandatangani gabungan timestamp dan raw JSON body:
signature = "sha256=" + HMAC_SHA256(secret_anda, timestamp + "." + raw_body)

webhook-handler.js (Node.js) Express 
const express = require("express");
const crypto = require("crypto");

const app = express();
const WEBHOOK_SECRET = "whsec_contoh_secret_anda_12345";

// PENTING: Gunakan raw body untuk verifikasi signature
app.post("/api/callback", express.raw({ type: "application/json" }), (req, res) => {
    const signatureHeader = req.headers["x-nexshop-signature"];
    const timestamp = req.headers["x-nexshop-timestamp"];
    const rawBody = req.body.toString("utf8");

    if (!signatureHeader || !timestamp) {
        return res.status(400).send("Missing signature headers");
    }

    // 1. Hitung expected signature
    const expectedSignature = "sha256=" + crypto
        .createHmac("sha256", WEBHOOK_SECRET)
        .update(timestamp + "." + rawBody)
        .digest("hex");

    // 2. Bandingkan dengan timing-safe comparison
    if (!crypto.timingSafeEqual(Buffer.from(signatureHeader), Buffer.from(expectedSignature))) {
        return res.status(401).send("Invalid signature");
    }

    // 3. Parse JSON & proses transaksi
    const payload = JSON.parse(rawBody);
    console.log("Callback diterima:", payload.data.ref_id, payload.data.status_message);

    // 4. Selalu balas HTTP 200 OK
    res.status(200).json({ received: true });
});

app.listen(8000, () => console.log("Webhook server running on port 8000"));
callback.php Native PHP 
<?php
$secret = "whsec_contoh_secret_anda_12345";

// Ambil raw body dan headers

$timestamp = $_SERVER['HTTP_X_NEXSHOP_TIMESTAMP'] ?? '';

echo json_encode(["received" => true]);
main.py (FastAPI) Python 3 
from fastapi import FastAPI, Request, HTTPException, Header
import hmac, hashlib

app = FastAPI()
WEBHOOK_SECRET = "whsec_contoh_secret_anda_12345"

@app.post("/api/callback")
async def receive_webhook(
    request: Request,
    x_nexshop_signature: str = Header(None),
    x_nexshop_timestamp: str = Header(None)
):
    if not x_nexshop_signature or not x_nexshop_timestamp:
        raise HTTPException(status_code=400, detail="Missing signature headers")
    
    raw_body = (await request.body()).decode("utf-8")
    
    signed_payload = f"{x_nexshop_timestamp}.{raw_body}"
    expected_sig = "sha256=" + hmac.new(
        WEBHOOK_SECRET.encode("utf-8"),
        signed_payload.encode("utf-8"),
        hashlib.sha256
    ).hexdigest()
    
    if not hmac.compare_digest(x_nexshop_signature, expected_sig):
        raise HTTPException(status_code=401, detail="Invalid signature")
    
    payload = await request.json()
    print("Trx update:", payload["data"]["ref_id"])
    return {"received": True}

Jadwal Retry Otomatis & Anti-Duplikasi

Sistem Relay NexShop didesain tahan banting (resilient) agar callback tidak pernah hilang meskipun server reseller sempat offline.

schedule Jadwal Retry Bertingkat

Jika server Anda gagal merespons dengan HTTP 2xx (misal: timeout 10s, 500 internal server error, atau connection refused), poller NexShop akan menjadwalkan percobaan ulang otomatis:

  • Percobaan 1: Pengiriman langsung (real-time).
  • Percobaan 2: +1 Menit setelah kegagalan pertama.
  • Percobaan 3: +5 Menit setelah kegagalan kedua.
  • Percobaan 4: +15 Menit setelah kegagalan ketiga.
  • Percobaan 5: +1 Jam (60 Menit).
  • Percobaan 6: +3 Jam (180 Menit). Status menjadi dead jika tetap gagal.

fingerprint Idempotensi & Anti-Duplikasi

NexShop menyertakan header X-NexShop-Delivery (UUID unik) dan menggunakan key unik ref_id:status. Jika provider jaringan mengirimkan notifikasi ganda dengan status yang sama, sistem relay tidak akan membombardir server Anda dengan data berulang.

help Bab 12

Pertanyaan Umum (FAQ Reseller)

Jawaban atas pertanyaan seputar akun reseller dan integrasi teknis.

Apakah pendaftaran reseller dipungut biaya?

Tidak. Pendaftaran program reseller NexShop 100% gratis tanpa biaya pendaftaran maupun iuran bulanan.

Bagaimana cara mendapatkan Webhook Secret?

Webhook Secret (whsec_...) dibuat otomatis saat URL endpoint didaftarkan di dashboard admin. Hubungi Admin NexShop via WhatsApp untuk mendaftarkan URL callback dan mendapatkan secret key toko Anda.

Apakah URL Webhook harus menggunakan HTTPS?

Ya. Demi keamanan transmisi data transaksi dan perlindungan data pengguna, target URL webhook wajib menggunakan protokol HTTPS yang valid.

Berapa batas waktu timeout respon webhook?

Server Anda diharapkan memberikan HTTP status 200 OK dalam kurun waktu maksimal 10 detik. Disarankan untuk memproses transaksi secara asynchronous di latar belakang (background queue).
